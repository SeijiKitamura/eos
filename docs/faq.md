# Q&A

[← 仕様書に戻る](../specification.md)

### Q1. ファイル名は固定ですか？変動しますか？

固定です。`eXXXX.csv`（Xは4桁の数字）となります。

### Q2. 前日分のファイルは残りますか？

午前6時より前であれば、前日分のファイルが残っています。
午前6時以降は、発注日が当日のデータのみが作成されるため、前日分は残りません。

### Q3. 追加発注は同じ伝票番号への行追加になりますか？

いいえ。追加した分には、新しい伝票番号が付与されます。

### Q4. 追加があった場合は追加した分だけのデータが作成されますか？

いいえ。既存のデータに追加分が加わった状態でCSVが作成されます。
そのため、一度取り込んだ後に追加分を取り込む際は、既存データとの重複に対する対応が必要です。

（詳しい挙動は [データ作成スケジュール](data-schedule.md) を参照してください）

### Q5. 発注がない日に空のファイルは作成されますか？

いいえ。該当する発注がない場合、ディレクトリは空になります。

### Q6. 定められたリードタイムよりも先の納品日で発注されますか？

はい。発注日は当日のまま、納品日だけが先の日付になる発注データを作成できます。

### Q7. 受信（FTPダウンロード）はいつ行えばよいですか？

システムとしては **6:00〜21:45** の間でお願いしています。
15分ごとにデータを作成しているため、その時間帯の **3分・18分・33分・48分** にダウンロードいただくのがおすすめです。
回数や時間帯について、現時点で制限はありません。

### Q8. 1日に複数回受信（FTPダウンロード）を行っても大丈夫ですか？

はい。むしろ推奨しています。
1回目は通常の発注分、2回目はリードタイムより先の納品日で発注されたデータ、というように使い分けていただくことを想定しています。

### Q9. 表示している単価、売価は税抜ですか？

はい。すべて税抜価格です。

### Q10. 8桁JANはどのように表現されていますか？

8桁のまま使用しています。前ゼロの付与や空白での桁埋めは行っていません。
桁数に関わらず、すべてのJANコードで商品と同じバーコードを使用しています。

### Q11. テストはできますか？

はい、可能です。お申し出いただければ、1週間以内にご用意します。

### Q12. EOS発注までのスケジュールを教えてください。

既存の発注方法と併用する形でEOS発注を開始し、一定のテスト期間を経てEOS発注のみに切り替えます。

**例**：2026年8月15日時点でFAX発注を行っており、2026年9月1日よりEOS発注に切り替える場合

| 期間 | 状態 |
| --- | --- |
| 〜2026年8月31日 | 既存発注（FAX等）のみ |
| 2026年8月20日ごろ〜8月31日 | 既存発注とEOS発注を併用 |
| 2026年9月1日〜 | EOS発注のみ |
